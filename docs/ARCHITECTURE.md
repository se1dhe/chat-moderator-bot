# RedQueen Security — Architecture

> Мастер-документ по продукту — [PROJECT_PLAN.md](./PROJECT_PLAN.md). Здесь — технический разбор.

> Публичный SaaS-бот для модерации Telegram-групп и каналов. Продвинутый аналог
> @GroupHelpBot с объяснимой AI-модерацией. Тема и голос — RedQueen из «Resident Evil».

## 1. Продуктовая идея

RedQueen устанавливается администратором в любую группу или канал и берёт на себя
защиту входа, антиспам, антифлуд, фильтры контента, роли и аналитику. Ключевое
отличие от конкурентов — **объяснимая AI-модерация**: бот не «магически» банит, а
кладёт спорное сообщение в карантин и показывает админу карточку решения с причиной,
уверенностью модели и кнопками «Забанить / Простить / Правило». Человек остаётся в
контуре принятия решений.

Модель монетизации — freemium **на каждый чат**: базовая модерация бесплатна, AI-режим
и продвинутые фичи — в Pro-подписке через Telegram Stars.

## 3. Модель данных (ядро)

- **Chat** — подключённый чат/канал: `telegram_id`, `type`, `title`, `lang`, `added_at`.
- **User** — глобальный профиль пользователя (кросс-чат репутация в перспективе).
- **ChatMember** — связка user↔chat: роль, статус, exemption (иммунитет к модерации).
- **ChatSettings** — JSON-настройки чата: captcha, antiflood, фильтры, night mode,
  AI-режим (off / quarantine / autoban), порог уверенности.
- **Warn** — предупреждение: `chat`, `user`, `issued_by`, `reason`, `created_at`, `active`.
- **ModAction** — аудит-лог любого действия (ban/kick/mute/warn/unban/ai_quarantine).
- **AIVerdict** — вердикт модели по сообщению: категория, score, объяснение, статус
  (pending / approved / rejected), решение админа.
- **Subscription** — Pro-подписка чата: план, `active_until`, платёжный ledger.
- **Payment** — запись о платеже Stars (для сверки и возвратов).

Все таблицы с `chat_id` индексируются по нему; аудит и вердикты партиционируемы по дате.

## 4. Слои приложения

```
Telegram ──(webhook/polling)── aiogram Dispatcher
                                     │
          ┌──────── middlewares ─────┴───────────┐
          │  DB session · i18n · throttling · ACL │
          └──────────────┬────────────────────────┘
                         │ routers
   ┌───────────┬─────────┼──────────┬─────────────┐
 common     moderation  settings   ai_review    payments
   │           │          │           │             │
   └─────── services (бизнес-логика, без aiogram) ──┘
                         │
          ┌──────────────┼───────────────┐
        repo (БД)    ai.provider      redis
                    (Ollama/rules)
```

Хендлеры тонкие: разбор апдейта → вызов сервиса → ответ. Вся логика в `services/`,
чтобы её можно было тестировать и переиспользовать из Mini App API.

## 5. AI-пайплайн

1. Входящее сообщение проходит быстрые rule-фильтры (banned words, ссылки, флуд).
2. Если правило не сработало однозначно, сообщение идёт в **очередь AI-анализа**
   (async, с лимитом на чат и graceful fallback при недоступности Ollama).
3. `AIProvider.classify()` → категории (spam/scam/toxicity/nsfw/flood/ok), score,
   короткое объяснение. Провайдер абстрактный: `OllamaProvider` (Qwen) или
   `RuleProvider` (fallback без AI).
4. По порогу и режиму чата:
   - **quarantine** — сообщение скрывается/помечается, админу шлётся карточка решения;
   - **autoban** (Pro, высокий порог) — действие применяется автоматически + лог;
   - **off** — только логирование.
5. Мультимодальность (этапы позже): vision для изображений/GIF, ключевые кадры видео,
   ASR для голосовых, безопасный extractor для документов — всё через ту же очередь.

Runtime — абстракция: смена модели (qwen3:4b → qwen3:8b/14b) конфигом без изменения кода.

## 6. Приватность и соответствие

Telegram требует прав администратора для ограничений/удаления и отключённого Privacy
Mode, чтобы бот видел поток сообщений. Onboarding обязательно это запрашивает.
Модерационные данные: retention настраивается на уровне чата, есть экспорт и удаление
по запросу админа. Секреты только в `.env` (в `.gitignore`), в код/логи не попадают.
