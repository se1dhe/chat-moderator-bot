## 1. Видение и позиционирование

**RedQueen Security** (@RedQueenSecurity_Bot) — публичный SaaS-бот для модерации
Telegram-групп и каналов. Продвинутый аналог @GroupHelpBot с ключевым отличием —
**объяснимой AI-модерацией**: бот не «магически» банит, а кладёт спорное сообщение в
карантин и показывает администратору карточку решения (причина, категория, уверенность
модели, кнопки действий). Человек остаётся в контуре.

Персона и голос — ИИ-система безопасности «Red Queen» из франшизы *Resident Evil*
(«Улей»): холодная, точная, узнаваемая. Отсылки к лору выражены **сильно**, но тексты
остаются понятными и никогда не токсичны к пользователям.

Модель: глобальный SaaS на одном управляемом сервере, freemium **на каждый чат**.

## 3. Скоуп чатов и права Telegram

Бот работает в супергруппах и каналах. Ограничения платформы, которые определяют
onboarding:

- Для банов/ограничений/удаления боту нужны **права администратора** (Ban users,
  Restrict members, Delete messages).
- При включённом **Privacy Mode** бот не видит весь поток сообщений — для AI-модерации
  и антиспама Privacy Mode **должен быть отключён** (`@BotFather → /setprivacy → Disable`).
- Комментарии в каналах технически являются привязанной discussion-группой и
  подключаются отдельно как группа.

Onboarding обязан проверять наличие прав и статуса Privacy Mode и вести админа за руку.

## 5. Архитектура (сводка)

```
Telegram ──(polling dev / webhook+ngrok)── aiogram 3 Dispatcher
                                  │  middlewares: DB session · i18n · throttling · ACL
                                  │  routers: common · moderation · settings · ai_review · payments
                                  ▼
                            services/ (бизнес-логика, без aiogram)
              ┌───────────────────┼───────────────────┐
          db.repo (Postgres)   ai.provider          redis
                             (Ollama/Qwen | rules)  (rate-limit, FSM, raid-счётчики)
```

Хендлеры тонкие: апдейт → сервис → ответ. Вся логика в `services/`, чтобы переиспользовать
из будущего Mini App API и покрывать тестами. Полный технический разбор — в ARCHITECTURE.md.

**Multi-bot задел (для M5 white-label):** все данные ключуются по `chat_telegram_id`; токен
бота и идентичность выносятся в конфиг-слой, чтобы позже поднимать несколько экземпляров
над общей БД без переписывания домена.

## 6. Модель данных

Ядро (реализовано в M1): `Chat`, `ChatSettings` (JSONB для гибких полей), `User`
(поле `trust_score` под Adaptive trust), `Warn`, `ModAction` (аудит), `AIVerdict`
(объяснимые вердикты), `Subscription` (Pro на чат).

Расширения по релизам: `Payment` (ledger Stars, M4), `CaptchaSession` (M2),
`RaidEvent` (M3), `MediaVerdict` (M5), `CustomCommand` / `AutoReply` (M2–M3).

Все таблицы с `chat_telegram_id` индексируются по нему; аудит и вердикты партиционируемы
по дате. Retention: полный аудит по умолчанию, удаление/экспорт по запросу админа.

---

## 7. AI-пайплайн

1. Быстрые rule-фильтры (banned words, ссылки, флуд) — синхронно, дёшево.
2. Неоднозначное → очередь AI-анализа (async, лимит на чат, graceful fallback при
   недоступности Ollama → `RuleProvider`).
3. `AIProvider.classify_text()` → категория (ok/spam/scam/toxicity/nsfw/flood), score
   0–100, короткое объяснение.
4. По режиму чата и порогу: `off` (только лог) · `quarantine` (карточка решения) ·
   `autoban` (Pro, высокий порог, авто + лог).
5. Мультимодальность (M5): vision для изображений/GIF, ключевые кадры видео, ASR
   голосовых, безопасный extractor документов — через ту же очередь.

Runtime — абстракция: смена модели (qwen3.5:4b → 9b/27b) через env без изменения кода.

## 8. Монетизация (Telegram Stars)

- **Free**: базовая модерация, captcha, антифлуд, warns, кастомные команды (лимит).
- **Pro (на чат)**: AI-модерация (quarantine/autoban), Raid shield, trust score,
  расширенная аналитика, бэкапы, мультимодальность, без лимитов на команды/автоответы.
- Оплата — Telegram Stars (XTR) внутри бота/Mini App. Нужен проверяемый **ledger**
  (`Payment`) и обработка возвратов. `Subscription.active_until` гейтит фичи; при
  истечении чат откатывается на Free без потери данных.

---

## 9. Приватность и соответствие

Полный аудит действий и вердиктов включён по умолчанию (ценность для админов и
разбора инцидентов). Обязательные контроли: удаление данных чата по запросу, экспорт,
настройка retention на уровне чата. Секреты только в `.env` (в `.gitignore`), в код и
логи не попадают. При работе в ЕС-аудитории держим в уме GDPR (право на удаление,
минимизация в текстах вердиктов).

---

## 10. Интернационализация

EN + RU + UK с первого релиза. Строки персоны и системные тексты выносятся в
per-locale каталоги; язык определяется настройкой чата (`Chat.lang`) с фолбэком на
`DEFAULT_LANG`. Персона RedQueen адаптируется под каждый язык, сохраняя тон.

## 11. Деплой и окружения

- **Dev (сейчас):** локально, polling; Postgres/Redis в Docker; Ollama нативно на
  Apple Silicon (GPU). Webhook — через ngrok при необходимости.
- **Prod:** VPS + Docker Compose (postgres, redis, bot; ollama — отдельный профиль/сервер).
  Webhook на постоянном домене с `WEBHOOK_SECRET`. Миграции — Alembic (не `create_all`).
- Схема секретов и переменных — в `.env.example`.

## 12. Релизы

Легенда критериев готовности (DoD): код + миграции + тесты ключевой логики + запись в
CHANGELOG + ручная проверка в тестовом чате.

### M1 — Каркас и базовая модерация ✅ (сделано)
Конфиг, БД+модели, ядро aiogram, DI-мидлвари, ACL-фильтр админа, `/start`+`/help`,
`ban/kick/mute/unmute/warn/unwarn/unban/purge`, warn-лимиты с авто-действием, настройки
чата, аудит-лог, AI-listener с карточкой карантина (rule-fallback), Docker/Alembic.
**DoD:** ✅ команды работают, логика покрыта smoke-тестами, всё компилируется.

### M2 — Защита входа, антиспам, i18n
- Captcha (кнопка/математика/эмодзи), карантин новичков, авто-кик по таймауту, join-заявки.
- Антифлуд на Redis, лимиты медиа, блок ссылок/форвардов/упоминаний.
- Banned words (regex + списки), night/silent/slow mode, exemptions по ролям.
- i18n-каркас (EN/RU/UK), онбординг с проверкой прав и Privacy Mode.
- **DoD:** новичок проходит captcha; флуд/ссылки блокируются; тексты на 3 языках.

### M3 — AI-модерация (killer P0)
- Ollama+Qwen, очередь анализа, пороги на чат, режимы off/quarantine/autoban.
- Explainable карточки вердиктов (уже заложено — довести до прод-качества).
- **Raid shield**: детект наплыва (Redis-окна по join/сообщениям), авто-лок + алерт.
- Каркас **Adaptive trust score** (накопление сигналов, влияние на строгость проверок).
- **DoD:** AI-карантин работает end-to-end; raid-лок срабатывает на симуляции наплыва.

### M4 — Монетизация и Mini App
- Telegram Stars: Pro-подписка на чат, `Payment` ledger, возвраты, гейтинг фич.
- Mini App: правила, AI-очередь, роли, аналитика; EN/RU/UK.
- **DoD:** оплата Stars включает Pro в чате; Mini App показывает очередь и настройки.

### M5 — Мультимодальность, масштаб, white-label
- Vision (картинки/GIF), ключевые кадры видео, ASR голосовых, document extractor.
- Adaptive trust score в полном объёме, кросс-чат репутация, шаринг чёрных списков.
- Clone-боты / white-label (multi-bot над общей БД).
- **DoD:** скам-картинка ловится; можно поднять второй бренд-бот из конфига.

## 13. Стратегия качества

Темп — «качество важнее скорости». Практики: Alembic-миграции с M2 (не `create_all` в
prod), pytest на сервисный слой и фильтры, `Dispatcher.feed_update()` для интеграционных
тестов хендлеров, ruff-линт, типизация, аудит-лог как основа воспроизводимости решений.
Навык Codex `aiogram-3-development` запрещает API 2.x — держимся его правил.

## 14. Риски и ограничения

- **Telegram API:** права/Privacy Mode обязательны — снимаем онбордингом.
- **Ресурсы AI:** локальная модель упирается в RAM/GPU — модель сменная, есть fallback.
- **Скам эволюционирует:** правила стареют — AI + обновляемые списки, обратная связь от админов.
- **Приватность:** полный аудит ↔ GDPR — обязательны экспорт/удаление и минимизация в вердиктах.
- **Стоимость масштаба:** очередь и лимиты на чат, чтобы AI не заваливал сервер.
